# Pushing TCN Trading System to GitHub

## Step-by-Step Instructions

### 1. Create Repository on GitHub

Go to [github.com/new](https://github.com/new) and create a new repository:
- **Name**: `tcn-trading-system` (or your preferred name)
- **Description**: `Production-ready TCN-based trading system for next-bar prediction with risk management`
- **Visibility**: Private (recommended) or Public
- **DO NOT** initialize with README, .gitignore, or license (we have these locally)

### 2. Initialize Git Locally

Open Terminal and run:

```bash
cd "/Users/bencohen/Library/Mobile Documents/com~apple~CloudDocs/Files/Courses/TCN"

# Initialize git repo
git init

# Add all files
git add .

# Create initial commit
git commit -m "Initial commit - TCN trading system v1.0 baseline

- Complete layer-by-layer pipeline (data, windowing, training, backtest)
- 12 engineered features from OHLCV
- Causal TCN model (3 blocks, 32K parameters)
- Risk map with dead band and volatility scaling
- Comprehensive diagnostics at every layer
- Tested on SPY daily 2010-2021
- No trading edge detected (val AUC 0.50) but infrastructure solid"
```

### 3. Connect to GitHub

Replace `YOUR_USERNAME` with your GitHub username:

```bash
# Add remote
git remote add origin https://github.com/YOUR_USERNAME/tcn-trading-system.git

# Push to GitHub
git branch -M main
git push -u origin main
```

### 4. Verify Upload

Go to `https://github.com/YOUR_USERNAME/tcn-trading-system` and verify:
- ✅ All code files visible
- ✅ README displays correctly
- ✅ .gitignore working (no .venv, __pycache__, or .png files)

- User-specific (venv paths)
- Can be regenerated by running the system

## Git Best Practices

### Creating a Good .gitignore

Your current `.gitignore` is already set up correctly! It excludes:
- Virtual environments
- Python cache
- Large data files
- Model checkpoints
- Generated plots

### Tagging Versions

After initial push, create a baseline tag:

```bash
# Tag the current stable version
git tag -a v1.0-baseline -m "Baseline system - no edge but stable infrastructure"

# Push tags to GitHub
git push origin v1.0-baseline
```

### Branch Strategy

For future development:

```bash
# Keep main branch clean (always working)
git checkout -b feature/additional-features

# Make changes...
git add features/engineering.py
git commit -m "Add RSI and ATR features"

# Push feature branch
git push -u origin feature/additional-features

# When ready, merge via Pull Request on GitHub
```

## Git Commands Reference

### Daily Workflow:

```bash
# Check status
git status

# See changes
git diff

# Stage files
git add filename.py
# or stage all changes:
git add .

# Commit with message
git commit -m "Descriptive message"

# Push to GitHub
git push

# Pull latest changes
git pull
```

### Branching:

```bash
# Create and switch to new branch
git checkout -b feature/my-feature

# Switch branches
git checkout main

# List all branches
git branch -a

# Delete branch (locally)
git branch -d feature/my-feature
```

### Undo Changes:

```bash
# Discard changes to file
git checkout -- filename.py

# Unstage file
git reset HEAD filename.py

# Revert last commit (keeps changes)
git reset --soft HEAD~1

# Revert last commit (discards changes)
git reset --hard HEAD~1
```

## Security Notes

### DO NOT push to GitHub:

❌ API keys or secrets
❌ Personal data
❌ Trading account credentials  
❌ Proprietary data sources

### If you accidentally push secrets:

```bash
# Remove file from git history
git filter-branch --force --index-filter \
  "git rm --cached --ignore-unmatch path/to/secret/file" \
  --prune-empty --tag-name-filter cat -- --all

# Force push (careful!)
git push origin --force --all
```

**Better**: Use `.env` files (already in .gitignore)
